مرحلة التوليد (Code Generation)

بناءً على استفسارات عدد من الطلاب، نوضّح آلية عمل المشروع وملفات الدخل والخرج.

ا━━━━━━━━━━━━━━━
لدينا مرحلتان تعملان معًا:
1) معالجة البيانات وتعليمات Python (Flask).
2) معالجة قوالب Jinja وتوليد صفحات HTML.

ا━━━━━━━━━━━━━━━
■ ثانياً: المخطط العام

l ملف Flask (Python)
        ↓
   Python Parser
        ↓
   Python AST
        ↓
Semantic Analysis
   ↓
Generator
   ↓
Context Data (توليد المتغيرات والقيم)
        ↓
  render_template()
        ↓
l    ملف Jinja
        ↓
   Jinja Parser
        ↓
   Jinja AST
        ↓
l  تبديل المتغيرات
  {{ name }}  {{ age }}
        ↓
    HTML 
        ↓
 l    المتصفح

باختصار:
• Python → Bytecode → تنفيذ
• Jinja → AST → HTML

ا━━━━━━━━━━━━━━━
■ ثالثاً: ملفات الدخل (Input)

سيدخل إلى المترجم ثلاثة أنواع من الملفات:

1) ملف الباك إند: app.py
مثال:
products = [
    {"name": "Phone", "price": 300},
    {"name": "Laptop", "price": 800}
]

2) ملفات Jinja داخل مجلد templates/
• index.jinja
• add_product.jinja
• edit_product.jinja

مثال:
{% for product in products %}
<h3>{{ product.name }}</h3>
{% endfor %}

3) ملفات تصميم وتنسيق الواجهة
• style.css
• script.js (اختياري)

ملاحظة:

الملفات الناتجة عن مرحلة التوليد هي الملفات التي ينتجها المترجم مباشرةً بعد معالجة تعليمات Jinja وربطها بالبيانات المستخرجة من Python.

أما ملفات app.py وstyle.css وscript.js فهي ملفات داعمة لعمل التطبيق، ولا تدخل ضمن عملية التحليل والتوليد، لذلك تُحافَظ عليها وتُرفَق مع الخرج النهائي دون إجراء أي معالجة إضافية عليها.

■ خامساً: نقاط مهمة (لتفادي اللبس)

• في مرحلة التوليد، يُنفَّذ الجزء المسؤول عن تجهيز البيانات في Python ثم تُمرَّر القيم إلى قالب Jinja لتوليد صفحات HTML.

• لا نعتمد على جدول الرموز (Symbol Table) في مرحلة التوليد؛ فهو خاص بمرحلة التحليل الدلالي وفحص الأخطاء.

• أي تعديل على الواجهة (مثل إضافة منتج) يستلزم إعادة التوليد (render) ليتزامن الخرج مع البيانات
